部署指南 — 把应用交给别人用

场景：你把这套服务部署到公网，别人访问网址就能用。你配置一次，所有用户共用。
最重要的一句话：别人什么都不用填，也不用改代码。
你只需要在 apps/server/.env 这个文件里填一次高德 Key， 之后所有访问你网址的用户自动共用它。

一、先分清两本账

这个项目有两层配置，各管各的。搞混了就会以为"设置页漏做了高德配置"—— 其实它是故意不放在设置页的。

层级谁填填在哪包含什么
用户级 每个用户自己 网页「设置」页 模型 API Key——各人烧各人的 token
服务级 你（部署者） .env 文件，填一次 高德 Key、JWT_SECRET、加密主密钥、数据库地址

为什么高德 Key 不能放进设置页

三个现实原因，不是设计疏漏：

1. 申请门槛——高德 Key 需要注册高德开放平台并实名认证，让每个普通用户都走一遍不现实。
2. 账单归属——高德按 Key 计费，谁部署谁承担配额。
3. 域名白名单——JS Key 必须绑定具体域名（相当于门禁只认本小区的门牌号）。 别人就算拿到你的 Key，部署到自己的域名上地图也会直接报错，技术上借不了。

二、你只需要填这 3 个值

文件位置：apps/server/.env（若不存在，从 .env.example 复制一份改名）

变量名用途从哪里获取
AMAP_WEB_SERVICE_KEY 后端调 POI 搜索 / 路径规划 / 天气
绝不下发到浏览器		 高德控制台 → 应用管理 → 添加 Key → 选「Web服务」
AMAP_JS_KEY 浏览器加载地图用
必须出现在前端，靠域名白名单保护		 添加 Key → 选「Web端(JS API)」
AMAP_JS_SECURITY_CODE 与 JS Key 配套的安全密钥
2021 年后新建的 JS Key 强制要求		 创建 JS Key 时平台自动生成，两串一起给
这两种 Key 类型不同，不能混用 填错位置会得到「INVALID_USER_KEY」之类的报错。Web 服务 Key 拿去做地图渲染会失败， JS Key 拿去做后端请求也会失败。 
# apps/server/.env 里的样子（值换成你自己的）
AMAP_WEB_SERVICE_KEY="你的Web服务Key"
AMAP_JS_KEY="你的JS Key"
AMAP_JS_SECURITY_CODE="你的安全密钥"

三、上线前必做清单

  1. 给 JS Key 配上线上域名白名单 最容易漏
    高德控制台 → 找到那个 JS Key → 域名白名单 → 填入你的线上域名（如 travel.example.com）。
    不配的话，本地开发正常，一上线地图就白屏并报 INVALID_USER_SCODE。这是最常见的上线翻车点。
  2. 确认 DEFAULT_MODEL_API_KEY 保持为空 省钱关键
    当前你的配置已经是空的，保持原样。
    一旦填了它，所有"没在设置页配 Key"的用户都会消耗你这个 Key 的余额—— 那就变成你替全世界的用户掏模型钱了。
  3. 重新生成一套生产用的密钥
    别跟开发环境共用。两个值：JWT_SECRET（登录凭证签名）和 VAULT_MASTER_KEY（加密所有用户的 API Key）。 
    node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"  # JWT_SECRET
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"  # VAULT_MASTER_KEY（必须 64 位十六进制）
    ⚠️ VAULT_MASTER_KEY 一旦丢失，库里所有用户的模型 API Key 都再也解不开，无法恢复。
  4. 数据库从 SQLite 换成 PostgreSQL
    现在的 file:./prisma/dev.db 是单文件数据库，适合本地开发， 多用户并发写入时容易出问题。切换方式是在 prisma.config.ts 里换成 postgresql:// 连接串。
  5. 确认 .env 没被提交
    它已经被 .gitignore 排除，部署时用环境变量或服务器上的文件单独放置， 不要图省事塞进仓库。

四、两个需要你提前想清楚的敞口

敞口 1：注册接口完全开放 目前任何人都能访问你的网址自助注册账号，注册后就能使用你的高德配额。 如果只是给朋友用，建议加个注册邀请码，或干脆关掉注册改为手动开号。
敞口 2：没有请求频率限制 代码里没有 rate limit。虽然所有 POI / 路径 / 天气查询都走了 TTL 缓存 （同一城市、同一酒店短时间内重复查询不会重复消耗配额）， 但单个账号仍可以反复查询大量不同地点来刷爆你的日配额。 建议在高德控制台设置「日配额上限 + 用量告警」作为兜底。

五、钱到底花在谁身上

项目谁出钱说明
模型调用费用 用户自己 因为兜底 Key 为空，每人必须自带 Key（BYOK），烧各自账号的 token
高德调用配额 你 共用你的 Key。免费额度内不花钱，超出后按高德规则限流或计费
服务器与域名 你 常规部署成本
结论 只要保持 DEFAULT_MODEL_API_KEY 为空，你就不会替别人付模型钱。 唯一的成本敞口是你的高德配额，用「域名白名单 + 控制台配额告警 + 考虑关闭公开注册」三层挡住即可。
